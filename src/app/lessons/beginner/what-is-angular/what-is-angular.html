What is Angular?

Angular is a TypeScript framework for building scalable single-page web applications. The one idea to hold onto from day one: a framework is a machine that keeps the screen in sync with your data. You describe what the UI should look like for a given state; you change the state; Angular figures out the minimal DOM edits and applies them. You almost never touch the DOM yourself. Everything below builds on that sentence.

Framework vs library — why the distinction matters

A library (like React or jQuery) is code you call: you stay in charge of the app's structure and reach for the library when you need it. A framework like Angular is code that calls you: it owns the application lifecycle — bootstrapping, routing, rendering, dependency injection — and runs your components at the right moments. This is the "Hollywood principle": don't call us, we'll call you.

The practical payoff is that Angular is batteries-included: routing, forms, HTTP, testing and build tooling are all official, versioned together, and designed to fit. You trade some up-front learning for far fewer glue decisions later.

{{ counterSample }}
  • @Component({{ '{' }}…{{ '}' }}) — the decorator that turns a plain class into an Angular component and attaches its metadata.
  • selector: 'app-wa-counter' — the custom HTML tag you write to place this component: <app-wa-counter />.
  • template — the HTML this component renders. {{ '{{' }} count() {{ '}}' }} is interpolation: it prints the value and re-prints it whenever count changes.
  • (click)="count.set(count() + 1)" — event binding: run this expression on click. count.set(...) writes a new value into the signal.
  • count = signal(0) — a signal: a reactive box holding 0. Calling count() reads it; reading it inside a template subscribes that template to it.
  • doubled = computed(() => this.count() * 2) — a computed: a value defined by a formula. It recalculates only when a signal it read (count) changes, then only the DOM showing it updates.

Reactivity in the small — the cart total

Signals shine when data drives several things at once. This cart's item count and money total are both computed from one items signal. Add or clear items and every dependent piece stays correct — you never recompute the total or re-render a row by hand:

Live — one source of truth, several derived views

{{ cartSample }}
  • items = signal<…>([]) — the single source of truth: an array of cart lines, starting empty.
  • count = computed(() => this.items().length) — derived, so it can never disagree with the array.
  • total = computed(() => this.items().reduce(…)) — the sum, recomputed only when items changes (not on every render).
  • items.update((list) => [...list, newLine]) — we produce a new array. Assigning a new reference is what notifies the signal; mutating the old array in place would not.
  • @for (item of items(); track item.id) — template control flow: loop the array; track item.id gives each row a stable identity so Angular reuses DOM nodes instead of rebuilding the list.
  • {{ '{{' }} item.price | currency {{ '}}' }} — a pipe formats the raw number as money for display, without changing the underlying value.

How an app boots — main.ts line by line

Every Angular app starts from one call that mounts the root component and installs app-wide features:

{{ bootstrapSample }}
  • bootstrapApplication(App, …) — creates the root component App and renders it into the <app-root> tag in index.html.
  • providers: […] — app-wide dependency-injection registrations: things any component can ask for.
  • provideRouter(routes) — turns on the router and hands it your URL-to-component map.
  • provideHttpClient() — makes HttpClient injectable so components/services can call APIs.
  • No NgModule in sight — this is the modern standalone bootstrap (more on that below).

How a page actually renders (the pipeline)

  1. main.ts bootstraps the root component with the app-wide providers.
  2. The router reads the URL and picks the matching component (lazy-loading its code if needed).
  3. Angular instantiates that component, running its constructor and injecting whatever it asks for.
  4. The template renders, reading signals/inputs to produce the initial DOM.
  5. When a signal the template read changes, that view is marked dirty and Angular re-renders only the affected DOM in the next change-detection pass.
Mental model: state → template → DOM, and Angular owns the last arrow. Your job is to keep the state correct; keeping the pixels correct is the framework's job.

What makes Angular distinctive

  • TypeScript-first — even templates are type-checked, so a typo in a binding is a compile error, not a blank screen.
  • Opinionated & complete — one official answer for routing, forms and HTTP means less bikeshedding.
  • Dependency Injection — a powerful hierarchical DI system wires your services together.
  • Signals — fine-grained reactivity that enables precise updates and zoneless apps.
  • Tooling — the CLI, Language Service, DevTools and schematics come as one package.
  • Rendering options — client-side, server-side (SSR) and hydration are built in.

Common beginner misconceptions

"I need to update the DOM after changing my data."
No — that's the framework's entire job. Change the signal/property; the view follows. Reaching for document.querySelector in a component is almost always a sign you're fighting Angular.
"Angular is Angular.js / AngularJS."
Different frameworks. AngularJS (v1) is the legacy, discontinued one. "Angular" means v2+ — a full rewrite in TypeScript. This curriculum is modern Angular (v21).
"Every component needs an NgModule."
Not anymore. Standalone components declare their own imports and boot without any module. NgModules are legacy.
"Mutating an object updates the view."
Not reliably. Signals notify on assignment (a new reference). Prefer items.set(newArray) / items.update(...) over pushing into the existing array — you saw this in the cart demo.

Release cadence & ecosystem

Angular ships a major version roughly every 6 months, each with ~18 months of support and automated ng update migrations, so upgrades are routine rather than rewrites. It's maintained by Google and used across many of its own products. Because the router, forms, HTTP and testing tools are all official, an Angular codebase from one team looks a lot like the next — a real advantage on large or long-lived projects.

Key takeaways

  • A framework keeps the screen in sync with your data: state → template → DOM, and Angular owns rendering.
  • Components (template + class + styles) are the core unit; services + DI share logic; signals drive reactivity.
  • Interpolation shows values, event bindings change them, computed values derive from them — you rarely touch the DOM.
  • Modern Angular is standalone-first; NgModule snippets you find online are the legacy style.
  • Angular is batteries-included and TypeScript-first: more to learn up front, far less glue later.
