Control Flow: @switch

@switch renders exactly one branch based on a single value — ideal for state machines like idle / loading / success / error. It is the template equivalent of a switch statement, but with no break and no fall-through: the matched @case is the only one that renders.

Think of it as railway points

The word switch is not a metaphor here — it's the original meaning. A railway switch (the points) is the mechanism that decides which of several tracks a train takes. One train arrives, the points are set one way, the train goes down exactly one track. Everything about @switch follows from that picture:

  • One value, one track. The expression is evaluated once, then compared to each case. The train doesn't get re-weighed at every junction — that's what a chain of @if does.
  • No fall-through, because there's nowhere to fall. A train can't continue onto the next track after reaching the end of one. This is why there's no break: JavaScript's switch needs it precisely because it does keep going, and Angular's doesn't.
  • The other tracks aren't just empty — they were never laid. This is the part people miss and it matters far more than it sounds. A non-matching branch is not hidden; it is never constructed at all. No component instance, no DOM, nothing in change detection.

What actually gets built

Here is the difference between @switch and the CSS-based hiding people often reach for first. It's the single most consequential thing on this page:

Strict, and destructive. Strict: @case compares with ===, always — 1 will never match '1', and no case matching just renders nothing at all, silently. Destructive: the branch you leave is destroyed, not hidden, so its component state does not survive a round trip.

@switch / @case / @default

@switch (status()) { @case ('idle') {

💤 Nothing happening yet.

} @case ('loading') {

⏳ Loading your data…

} @case ('success') {

✅ Loaded successfully!

} @default {

❌ Something went wrong.

} }

Matching is strict equality (===). @default is optional — if nothing matches and there's no default, the block renders nothing. The switch expression is evaluated once per change detection, then compared to each case; a chained @if re-evaluates a fresh boolean at every rung.

Per-case type narrowing (the real superpower)

Switch on the discriminant of a tagged union and Angular narrows the type inside each @case — so branch-specific fields are available and type-checked. Pair it with @let to name the value once:

Live — one union, three shapes

@let s = shape(); @switch (s.kind) { @case ('circle') {

⬤ Circle · radius {{ s.radius }} → area = π·r² = {{ area() }}

} @case ('square') {

◼ Square · side {{ s.side }} → area = s² = {{ area() }}

} @case ('triangle') {

▲ Triangle · {{ s.base }}×{{ s.height }} → area = ½·b·h = {{ area() }}

} }

Inside @case ('circle'), s.radius compiles; s.side would not — the compiler knows s is the circle variant there. That's the same narrowing a TypeScript switch (s.kind) gives you, now in the template.

When to use @switch vs a chain of @if

@switch chained @if / @else if
Shape of the test one value vs several constants unrelated boolean expressions
Evaluation expression once, then === per case a new condition evaluated per rung
Type narrowing narrows the discriminant per case narrows only what each condition proves
Reads best for state machines, enums, union tags ranges, combined conditions, feature flags

Under the hood

  • One embedded view per branch. @switch compiles the same way as an @if/@else if chain: each @case/@default becomes its own conditional template function, and only the matching branch is ever instantiated as an embedded view — its component tree is the only one created and the only one that enters change detection.
  • Not a jump table — a sequence of === checks. The switch expression is evaluated once, then compared top-to-bottom against each @case literal by strict equality until one matches (or @default catches the rest). There's no compiled lookup table like a low-level switch statement might use.
  • Switching away destroys, it doesn't hide. Because non-matching branches are never instantiated, moving from 'loading' to 'success' runs the spinner component's ngOnDestroy and constructs the results component fresh — unlike [hidden], which never removes anything from the DOM.
  • No directive instance at runtime. Legacy *ngSwitch/ *ngSwitchCase are real directives holding a ViewContainerRef and toggling embedded views imperatively. @switch is compiled directly into conditional instructions by the template compiler — there's no NgSwitch object to inject or override.
  • @default is just another branch. It has no special runtime behavior beyond being the branch selected when no @case strictly matches — it's compiled the same way as every other branch.

Check yourself

Pitfalls that show up in exams & code review

  • Strict ===, including for objects. @case (someObj) matches only the same reference, never a structurally-equal one. Switch on a primitive discriminant (a string/number tag), not an object.
  • No multi-value case. You can't write @case ('a', 'b') or stack labels. Give each value its own @case, or fold the rest into @default.
  • No fall-through. Exactly one branch runs — there's no break and no cascading, unlike a JS switch.
  • Silent empty render. No matching case and no @default = nothing shown. Add a @default if "unknown state" should be visible.
  • Number vs string cases. @case (1) won't match the string '1'. Keep the switch value and the case literals the same type.

Exam corner

Does a @case need a break?
No. There's no fall-through, so no break. Only the first strictly matching case renders.
Nothing renders and there's no error — why?
No case matched and there's no @default. Either the value's type/spelling differs from the case literals, or you need a default branch.
How do I access variant-specific fields safely inside a case?
Switch on the union's discriminant (@switch (s.kind)). Angular narrows s to that variant inside each @case, so the branch's fields type-check.

Key takeaways

  • @switch (value) picks one @case by strict equality; @default is the optional fallback.
  • No break, no fall-through, no multi-value case — one branch renders.
  • Switching on a union discriminant narrows the type inside each case.
  • Reach for @switch for one-value-many-states; use a @if chain for unrelated booleans.
