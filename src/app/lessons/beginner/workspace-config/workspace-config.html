Workspace Configuration: package.json, angular.json & tsconfig

Three files govern everything that happens before your code runs: package.json says what to install, angular.json says how to build, and the tsconfig family says how to compile TypeScript. Knowing which knob lives where turns "mystery build errors" into five-minute fixes.

The mental model: building a house

Three files, three jobs, and the confusion is almost always about which one owns a given knob. Picture a building site:

  • package.json is the materials order — what gets delivered to the site, and which of it is scaffolding that goes home again versus timber that stays in the walls.
  • angular.json is the build plan — which crew does which job, in what order, and what the finished house has to weigh.
  • tsconfig is the building code — the rules your work is inspected against before anyone is allowed to move in.

You would not phone the lumber yard to change the floor plan. Most "mystery build errors" are exactly that call: editing the wrong file for the problem you have.

The three layers

package.json

The npm manifest: dependencies vs devDependencies, the scripts command palette, and the semver ranges the lockfile pins down.

angular.json

The CLI workspace: which builder runs each target (build / serve / test), global styles & scripts, assets, budgets, and named configurations like production.

tsconfig*.json

The compiler: one base config with shared strictness, extended by tsconfig.app.json (app files) and tsconfig.spec.json (test files).

Install → Build → Compile. package.json installs, angular.json builds, tsconfig compiles. When you do not know which file to edit, ask which of those three verbs your problem belongs to.

package.json — what to install and how to run

dependencies ship with the app (framework code that ends up in your bundles); devDependencies are build-time tools — the CLI, the compiler, the test runner. A deploy pipeline running npm ci --omit=dev skips the tooling entirely. 

{{ packageJsonSample }}
^ vs ~ vs nothing: ^20.1.0 accepts any compatible minor/patch (<21.0.0), ~20.1.0 accepts only patches (<20.2.0), and a bare version is exact. Ranges express intent — package-lock.json guarantees reality by freezing the entire resolved tree. Commit the lockfile; deleting it to "fix" an install is how works-on-my-machine bugs are born.

angular.json — how the CLI builds

Each project maps architect targets to a builder plus options. ng build -c production selects a named configuration whose options override the defaults for that run: 

{{ angularJsonSample }}
  • styles / scripts — global bundles injected into index.html (a classic name collision with package.json's "scripts": npm scripts are commands, these are files).
  • assets — files copied verbatim to the output (images, fonts, favicon).
  • budgets — size thresholds; exceed maximumError and the BUILD FAILS.
  • configurations — production enables optimization, output hashing and budgets; development keeps sourcemaps and fast rebuilds. fileReplacements is the traditional environment-file swap.
angular.json is read ONCE when the dev server boots. Source files are watched; workspace config is not — edit it and restart ng serve.

The tsconfig family — one base, two leaves

File Role Key contents
tsconfig.json Base ("solution") config every leaf extends strict, target, module, angularCompilerOptions.strictTemplates
tsconfig.app.json The application compilation files: main.ts · excludes *.spec.ts
tsconfig.spec.json The test compilation includes spec files · "types" adds the runner globals (describe/it)

The split exists because the two compilations need different file sets AND different ambient types: describe exists only where the test runner's type package is listed. Sweep spec files into the app build and CI greets you with "Cannot find name describe".

strictTemplates is the single highest-value flag to verify in an existing repo: it extends type-checking into templates, so a wrong-typed [input], a misspelled interpolation member, or an untyped $event fails the build instead of a user's session.

Key takeaways

  • package.json = install & run · angular.json = build · tsconfig = compile.
  • dependencies ship, devDependencies build; ranges express intent, the lockfile pins reality.
  • angular.json's styles/scripts arrays are GLOBAL bundles — and config edits need a server restart.
  • Budgets make bundle size a CI failure instead of a production surprise.
  • One base tsconfig, two leaves: app excludes specs; spec adds test-runner types.
