You typed ng new my-app, hit enter, and thirty seconds later had a running website — with tests, a dev server, and a dozen or so files you never typed a single line of yourself. This lesson is about knowing what showed up, why each piece lives where it does, and the two files people reach for by reflex and get wrong.

The analogy

Think of ng new as a contractor handing you a move-in-ready house.

You didn't pour the foundation or run the wiring — a contractor did all of that before handing you the keys. You still need to know which door is the front door, which switch controls what, and where the mail actually goes. That's exactly the deal ng new offers: it builds the whole house in thirty seconds, and your job is to learn the floor plan it left you, not to have built it yourself.

One door, one key. Every visit to the app — every single time it starts — walks through this one file first. Nothing else in the project runs before it. Electricity, water, whatever the house needs is already connected before you move in. Here, that's the router, the HTTP client — the services any room in the app can reach. Not something you carry around day to day, but the one document that says what the finished build is allowed to look like — and the first place to check when a build behaves oddly. Anything left in the mailbox is delivered exactly as left — nobody inside the house touches it, repaints it, or moves it. That's the entire deal a static asset gets.

Not just a version bump

How ng update keeps upgrades boring.

When Angular makes a breaking change, it ships a migration schematic alongside it. ng update doesn't just edit a version number in package.json — it runs that schematic against your actual source. Beats copy-paste

Generate schematics create a file and wire it up in the same step.

ng generate (ng g) doesn't just drop a file where you point it — it applies your project's conventions and can touch more than one file at once. Copy-pasting an existing component gets you a file; a schematic gets you a file that already fits.

Command Creates
ng g component x A standalone component (+ .spec.ts)
ng g service x An @Injectable() service
ng g directive x An attribute/structural directive
ng g pipe x A custom pipe class
ng g guard x A functional route guard
ng g interface x / enum x Plain TypeScript types

Questions from the back row

Before you go

Five things to remember.

  • ng new / serve / build / test / generate / update / add cover the everyday workflow — and only ng build (never ng serve) writes anything to dist/.
  • An app boots in one order: main.ts → app.config.ts's providers → app.routes.ts → App's single <router-outlet />.
  • Build settings live in angular.json, not package.json — package.json only holds dependencies and the npm scripts that shell out to the CLI.
  • A static file goes in public/ today, not src/assets/ — that folder stopped being the default back in Angular 17.
  • Schematics generate and wire up code in one step; ng update migrations rewrite it across an entire project when Angular ships a breaking change.
