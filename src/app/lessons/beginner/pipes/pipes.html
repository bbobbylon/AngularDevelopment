Built-in Pipes

A pipe transforms a value for display, right in the template, using the | operator. Pipes are pure functions of their input — they format data without ever mutating it.

You already know this symbol

Angular didn't invent |. It borrowed it from the Unix shell, and it means exactly the same thing there as here: 

# In a terminal — the output of each command feeds the next, left to right:
cat names.txt | sort | uniq
#              └─────┘ └─────┘
#              station  station

<!-- In an Angular template — same idea, same direction: -->
{{ '{{' }} now() | date:'fullDate' | uppercase {{ '}}' }}

So here's the mental model to carry through the rest of the page: a chain of pipes is an assembly line. A value goes in on the left and travels rightward through a row of stations; each one reshapes it and hands the result to the next. Three things follow from the picture, and they cover most of what people get wrong:

  • Order matters. Each station receives whatever the one before it produced — not the original value.
  • The flow is one-way. A pipe can't reach back and change now(). Your component's data is untouched; only the rendered string differs.
  • Types matter more than you'd think. uppercase expects a string. Put it before date instead of after and you're feeding a Date object into a string pipe — the station gets something it can't work with.

Number pipes (with parameters)

Live

number:'1.2-2' {{ num() | number: '1.2-2' }}
percent {{ num() / 100 | percent }}
currency:'USD' {{ num() | currency: 'USD' }}
currency:'EUR':'code' {{ num() | currency: 'EUR' : 'code' }}

The '1.2-2' means: at least 1 integer digit, 2–2 fraction digits.

Before the dot, a floor. After the dot, a range. Read digitsInfo as minInteger . minFraction - maxFraction. So '1.2-2' is "at least one digit on the left, exactly two on the right" — the 2-2 pins the fraction to precisely two places, which is why it's the standard money format. The trap is reading the dot as a decimal point in an example number. It's a separator between two settings, not a number.

Chaining pipes

Pipes compose left to right:

{{ '{{' }} now() | date: 'fullDate' | uppercase {{ '}}' }}
→ {{ now() | date: 'fullDate' | uppercase }}
The async pipe is special: it subscribes to an Observable or reads a Signal and auto-unsubscribes. It is covered alongside RxJS in the intermediate track. The keyvalue pipe lets you @for over an object's entries.

Iterating objects with keyvalue

Live

    @for (entry of settings() | keyvalue: (sorted() ? undefined : noSort); track entry.key) {
  • {{ entry.key }}: {{ entry.value }}
    • } 
{{ '{{' }} obj | keyvalue {{ '}}' }}             <!-- sorted by key, default -->
{{ '{{' }} obj | keyvalue: noSort {{ '}}' }}      <!-- pass a compareFn to keep insertion order -->

keyvalue turns an object (or Map) into an array of { key, value } pairs so @for can iterate it — plain objects aren't themselves iterable. It re-sorts on every call unless you supply your own stable compare function.

Purity & performance

Built-in pipes are pure: Angular memoizes the result and only re-runs transform() when the input reference changes. That makes {{ '{{' }} list | sort {{ '}}' }} cheap on every CD pass — far cheaper than calling a method. Arguments can be bound and dynamic (num() | number: format()).

currency, date, number and percent format according to LOCALE_ID. For non-default locales you must register the locale data (registerLocaleData()) and provide the locale, or those pipes throw at runtime.

Check yourself

Pitfalls that show up in exams & code review

  • Forgetting to import the pipe. Standalone components must list each pipe in imports (e.g. DatePipe) — a missing import gives "no pipe found".
  • Mutating an array and expecting a re-run. Pure pipes only re-run when the input reference changes. arr.push(x) won't trigger it — assign a new array.
  • Writing a stateful "impure" pipe. Impure pipes run every CD cycle and wreck perf; do filtering/sorting in the component (a computed signal), not a pipe.
  • Locale pipes without locale data. date/currency/ number throw for non-default locales unless you registerLocaleData() and provide LOCALE_ID.
  • Misreading the digits format. '1.2-2' is minInteger.minFraction-maxFraction — not "1 to 2".

Exam corner

What does "pure pipe" mean, and why does it matter?
Angular memoizes the result and only re-runs transform() when the input reference changes — so pipes are cheap on every change-detection pass. Mutating in place skips the re-run.
Decode number: '1.2-2'.
At least 1 integer digit, at least 2 and at most 2 fraction digits — i.e. minIntegerDigits.minFractionDigits-maxFractionDigits.
Where should list filtering/sorting live — a pipe or the component?
The component (a computed signal). A filtering pipe would have to be impure and run every cycle. Keep pipes pure and for display formatting.

Under the hood

  • A pipe is just a class with a transform() method. @Pipe({ name: 'uppercase' }) registers the class; Angular instantiates it once per binding site and calls pipeInstance.transform(value, ...args) — there's no special runtime magic beyond that.
  • Pure vs impure controls how often that call happens. A pure pipe (the default) only re-runs transform() when the input or its arguments change by reference/primitive equality. An impure pipe (pure: false) re-runs on every change-detection cycle — every keystroke, every timer tick, every unrelated signal update — which is why a stateful filtering/sorting pipe left impure can quietly wreck performance on a large list.
  • | async subscribes and unsubscribes for you. The first time a template evaluates obs$ | async, the pipe calls .subscribe() internally; when the view hosting it is destroyed (an @if toggles off, or the component itself is destroyed) the pipe's own ngOnDestroy calls .unsubscribe() — that's the entire trick behind "no manual subscription management".
  • keyvalue's default sort is itself just a pipe transform running Array.sort() over Object.keys()/Map entries on every invocation — which is why swapping in a no-op compare function (as above) is the standard way to preserve insertion order.
  • Locale-aware pipes wrap the platform Intl API, not hand-rolled formatting logic. DatePipe/CurrencyPipe/ DecimalPipe call into Intl.DateTimeFormat/ Intl.NumberFormat under LOCALE_ID — which is also why missing locale data throws at the Intl layer, not inside Angular.

Key takeaways

  • Syntax: value | pipeName: arg1 : arg2 — args can be bound/dynamic.
  • Built-ins live in @angular/common; import the ones you use.
  • Pipes are pure, memoized transforms for display — they never mutate the source.
  • Locale-aware pipes need the locale registered; chain pipes with multiple |.
