Class & Style Binding

Angular gives you several ways to drive an element's classes and inline styles from data — from single-toggle bindings to whole objects.

The mental model: sheets on an overhead projector

Picture the old classroom projector. The static class="box" is the bottom sheet, drawn once and never erased. Every binding you add lays another transparent sheet on top of it — [class] one sheet, [class.box--active] another. Nobody wipes anyone else's sheet clean; you see everything at once.

That single picture answers both of the questions people get wrong here. Why does class="box" survive a [class] binding that never mentions it? Because the binding is a different sheet. And when two sheets both draw box--active, which one do you see? The stack has a fixed order, and the per-class binding sits on top.

Bindings layer — they never replace. Static class, then [class] maps, then [class.x] on top. If a class you did not expect is still there, something below is still drawing it.

Single class & style bindings

Live

Styled box ({{ size() }}px) 
<div [class.box--active]="active()"
     [style.fontSize.px]="size()"
     [style.color]="color()">...</div>
[class.name]="bool" toggles one class. [style.prop]="val" sets one style; you can append a unit, e.g. [style.width.px] or [style.width.%].

That suffix is doing more work than it looks like it is. Drop it and nothing complains — which is precisely the problem: 

<div [style.width]="8">

// setProperty('width', '8')
// → invalid CSS, dropped by the browser
<div [style.width.px]="8">

// setProperty('width', '8px')
// → 8 pixels wide

Binding many classes / styles at once

Bind an object or array to [class] / [style]:

Live

state = {{ state() }} 
<div [class]="{{ '{' }} active: isActive(), error: hasError() {{ '}' }}"
     [style]="{{ '{' }} color: 'red', fontWeight: '600' {{ '}' }}">...</div>
Bound classes merge with the static class attribute — they don't replace it. Above, class="box" stays applied while [class] adds/removes the state classes. The same holds for style. When two bindings target the same class/style, the more specific one wins (e.g. [class.box--active] beats a key inside [class]), and !important is honoured in style strings.

NgClass & NgStyle directives

The ngClass and ngStyle directives predate the bindings above. They still work and accept strings, arrays or objects, but for new code the native [class] / [style] bindings are usually clearer and faster.

Under the hood

Here is the projector picture again, this time as the actual resolution order Angular runs on every change-detection pass:

  • Angular doesn't rebuild className from scratch. Each binding source — the static class attribute, a [class] map, per-class [class.x] bindings, ngClass — is compiled into its own styling instruction; the renderer merges them and, on each change-detection pass, diffs the new value against the last one.
  • Only the changed classes are patched. Angular calls classList.add/classList.remove (or style.setProperty/removeProperty) for just the entries that actually changed — it never touches classes/styles that came from a different binding source.
  • Static class and bindings coexist because they're separate layers. The literal class="box" is applied once at creation; bound classes are layered on top independently, which is why a [class] object that never mentions box can't remove it.
  • Collisions resolve by binding kind, not DOM order. When two bindings target the same class, Angular resolves it at the styling layer by priority — a per-class [class.x] binding always wins over a same-named key inside a [class] map — before the browser's CSS cascade/specificity ever gets involved.
  • Unit suffixes are string concatenation, not validation. [style.width.px]="8" just becomes style.setProperty('width', '8px'); Angular does no unit checking, so binding a value that's already a string ([style.width.px]="'8em'") produces the nonsensical "8empx".

Pitfalls that show up in exams & code review

  • Thinking [class] wipes the static class. It doesn't — bound and static classes merge. Same for [style].
  • Forgetting the unit suffix. [style.width]="8" sets width: 8 (invalid); use [style.width.px]="8" or bind a full string "8px".
  • Reaching for ngClass/ngStyle in new code. The native [class]/[style] bindings are faster and need no import.
  • Fighting specificity. When [class.active] and a key inside [class] target the same class, the specific binding wins — don't set the same class from two places.
  • camelCase vs kebab-case. In binding syntax use camelCase ([style.fontSize.px]); inside a bound object either works ({{ '{' }} 'font-size': … {{ '}' }}).

Key takeaways

  • [class.x] / [style.x] toggle or set a single thing.
  • [class] / [style] accept objects/arrays/strings for many at once.
  • Style bindings support unit suffixes like .px and .%.
  • Bound classes/styles merge with static ones; ngClass/ngStyle are legacy.
