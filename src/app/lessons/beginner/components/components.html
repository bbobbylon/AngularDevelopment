Components

Components are the fundamental building block of every Angular app. A component couples a template (what the user sees), a class (the data and behavior) and styles, all wired together by the @Component decorator.

Anatomy of a component

import {{ '{' }} Component, input {{ '}' }} from '@angular/core';

@Component({{ '{' }}
  selector: 'app-greeting-card',   // how you use it in a template
  imports: [],                     // components/directives/pipes it uses
  template: '<p>Hello, {{ '{{' }} name() {{ '}}' }}</p>',
  styles: ['p {{ '{' }} color: hotpink {{ '}' }}'],
{{ '}' }})
export class GreetingCard {{ '{' }}
  readonly name = input('Ada');
{{ '}' }}

Modern Angular components are standalone by default — no NgModule required. They declare their own dependencies in the imports array. The component below is rendered live; change the text and watch every instance update:

Every instance owns its own state

Each <app-greeting-card> tag above got its own GreetingCard instance — a separate object with its own fields, created fresh from the class. Click the 👏 button on one card; watch the others stay at zero:

One class, three instances, three separate claps signals in memory. Nothing you click on Ada's card can touch Grace's — that isolation is exactly what makes a component a reusable, self-contained unit.

templateUrl & styleUrl

For larger components you split the HTML and CSS into their own files using templateUrl and styleUrl instead of inline strings. This lesson uses an inline template so the whole concept lives in one file — both styles are equally valid.

Selector forms

The selector is a CSS selector, so a component can match more than an element tag:

selector: 'app-card'      // element:   <app-card>
selector: '[appCard]'     // attribute: <div appCard>
selector: '.app-card'     // class:     <div class="app-card">
selector: 'app-card, [appCard]'   // multiple — match either form

Style encapsulation

A component's styles are scoped to that component by default (ViewEncapsulation.Emulated) — Angular adds a unique attribute to its elements so p {{ '{' }} color: hotpink {{ '}' }} can't leak out and affect other components. Options:

  • Emulated (default) — scoped via attribute rewriting, no Shadow DOM.
  • ShadowDom — real browser Shadow DOM isolation.
  • None — styles become global. Use deliberately, rarely.

The full mechanics — the emitted CSS for each mode, :host, and the custom-property theming pattern for reaching a child's internals — are their own lesson: View Encapsulation.

Under the hood

  • The decorator is consumed at build time, not runtime. The Angular compiler reads @Component's metadata and the template string once, ahead of time (AOT), and emits a compiled component definition (ɵcmp) attached to the class — a template function made of low-level instructions (ɵɵelementStart, ɵɵtext, …), not the HTML string you wrote. By the time your app runs in the browser, there is no template parser left to invoke.
  • A component class is a factory, not a singleton. Every tag match creates a fresh instance via Angular's dependency injector, which is why the three GreetingCards above each got an independent claps signal — same class, three separate objects living in the view tree.
  • The class is plain data + methods; reactivity is bolted on by Angular. signal() and input() don't know anything about rendering — they're just reactive containers. It's the compiled template function, re-run by change detection, that reads them and patches the DOM. Swap signal for a plain field and the class still works in TypeScript; it just stops updating the screen.
  • A directive is a component missing a template. Structurally they're the same construct — a decorated class the compiler processes the same way — @Directive just skips the "produce a view" half. That's why a component technically is a directive with a template attached.

Exam pitfalls

  • Forgetting to import a child. Using <app-greeting-card> without adding GreetingCard to the parent's imports array fails at compile time — NG8001: 'app-greeting-card' is not a known element. Standalone components declare every dependency they use themselves.
  • template and templateUrl are mutually exclusive. Specifying both throws NG1001: Component has both template and templateUrl at build time — pick exactly one per component.
  • styles is a string array, styleUrl is a single string. Multiple external files use the plural styleUrls: [...]; mixing up singular/plural or array/string shape across Angular versions is a common exam trap.
  • The selector prefix is a lint convention, not a compiler rule. Angular will happily compile selector: 'greeting-card' with no app- prefix — it's the default angular.json lint config (and the style guide) that flags it, not a hard error.

Key takeaways

  • A component = decorator metadata + a template + a class + styles.
  • Standalone components import their own dependencies; no NgModule.
  • The selector is a CSS selector — element, attribute or class.
  • Styles are component-scoped by default (Emulated encapsulation).
  • Components compose — they nest inside one another to build a UI tree.
