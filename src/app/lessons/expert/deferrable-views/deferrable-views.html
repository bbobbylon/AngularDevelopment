@defer lazily loads a block of template — and every component, directive and pipe it uses — splitting them into a separate JS chunk that is only fetched when a trigger fires. It is the most granular code-split Angular offers, written directly in the template with no dynamic imports. This app uses it to defer lesson card grids until they scroll into view.

The problem

Every visitor downloads your whole app. Even the parts they'll never see.

A heavy charting library, a comments widget, an admin panel only 2% of visitors ever open — by default, every one of them ships to every visitor, in the same bundle as the code that actually renders on first paint. The browser downloads, parses and compiles all of it before your app is interactive, whether or not this particular visitor ever scrolls far enough to need it.

Without touching a bundler config, how would you tell Angular "only fetch this component's code if someone actually scrolls to it"? Keep a guess in your head — the four live demos below will confirm or correct it.

The mental model

@defer is a restaurant that cooks to order, not a buffet.

The buffet (the default): every dish is cooked in advance and sitting out under a heat lamp, whether or not anyone eats it. That's eager loading — every component bundled and shipped to everyone, whether or not anyone ever scrolls to it.

Made-to-order (@defer): the kitchen doesn't start cooking a dish until a ticket actually comes in. The menu card sitting on your table is the @placeholder — printed and ready before anyone orders anything. "Your order is being prepared" is the @loading state. The dish arriving is the real content. "Kitchen's out of that tonight" is @error.

Now the trap, and the reason it maps so cleanly: if that same dish is also sitting on the buffet line somewhere else in the restaurant — someone, somewhere, ordered it eagerly — the kitchen has to keep it prepped regardless. Ordering it à la carte at your table doesn't save the kitchen a single minute of prep, because the ingredients were already bought and cooked for the buffet. That's exactly what happens when the same component is also referenced eagerly anywhere else in your app.

Order first, cook second. A @defer block never starts fetching until its trigger fires — no ticket, no dish. One eager reference to the same component anywhere in the app forces it back into the main bundle. The @defer block still runs — placeholder, trigger, loading state — but the split it promised evaporates. Verify in the production build output, not by reading the template.

The mechanism

Four companion blocks, one lazy chunk.

Shown immediately, ships eagerly. Optional minimum time stops it flashing for one frame on a fast trigger. Also eager. after skips it for fast loads; minimum stops it blinking once it does appear. Rendered once the chunk is fetched. Every component, directive and pipe it uses splits along with it. Offline, or a deploy that pruned the chunk hash this build expects. Eager, same as the other companions.

The trigger vocabulary

Seven ways to say "now".

Trigger When it fires Mechanism
on idle (default) browser is idle requestIdleCallback
on viewport placeholder enters the viewport one shared IntersectionObserver
on interaction first click / keydown on the placeholder event listeners on the placeholder root
on hover first mouseenter / focusin same, hover events
on timer(2s) after the delay setTimeout
on immediate as soon as rendering finishes no waiting — but still async
when expr() expression becomes truthy — one-way, it never unloads normal change detection

Combine triggers (OR semantics): on hover; on timer(5s) loads whichever fires first. Point a trigger at another element: on viewport(heroRef). And prefetch on idle splits fetching from showing — the chunk downloads early while the placeholder stays up until the main trigger fires.

@defer (when showWidget()) { } @placeholder {

Waiting for showWidget() to be true…

}

Now click "set it back to false": the widget stays. @defer (when …) answers "when should this load", not "should this show" — loading is a one-way door. For show/hide semantics, nest an @if inside the loaded block.

Under the hood

What the compiler actually does.

  • The split is per-dependency, not per-block: the compiler collects the components/directives/pipes used inside @defer and rewrites their imports as dynamic import() — the bundler does the rest.
  • Only standalone dependencies are deferrable — NgModule-declared ones can't be split this way.
  • Triggers are cheap: all on viewport blocks share one IntersectionObserver; hover/interaction listeners attach to the placeholder's root node — which is why those triggers require a @placeholder (with a single root element) or an explicit element reference.

The exam trap

SSR: @defer vs incremental hydration.

Two very different behaviors, easy to confuse in an exam: with plain triggers, the server renders the placeholder (the content wasn't loaded on the server either) and the real content appears only after the client trigger fires. With hydrate triggers, the server renders the full content — users and crawlers see it immediately — and only its JavaScript (hydration) is deferred. Choose hydrate on viewport for SEO-relevant below-the-fold content, plain on viewport for content that may never be needed at all.

Pitfalls

Where this bites in practice.

  • Layout shift: a 40px placeholder replaced by a 600px chart yanks the page (CLS). Size placeholders like the real content — skeletons, fixed-height shells.
  • Deferring above-the-fold content: LCP now waits for a second network round-trip. Defer what's below the fold or optional — not the hero.
  • on immediate/on idle still flash: the chunk fetch is async, so there's always at least one placeholder frame. Use @loading (after 100ms) so fast loads never blink a spinner.
  • Shared dependency kills the split — the eager usage elsewhere wins (see the predict above). Verify with a production build: does the chunk actually exist?
  • @defer inside @for: legal, but N blocks = N triggers and N (cheap but real) registrations — for long lists prefer virtualization or one defer around the whole list.
  • viewport/hover/interaction without a placeholder is a compile error — the trigger needs a DOM node to observe. Give the placeholder a single root element.

Questions from the back row

Before you go

Recap — five things to remember.

  • @defer code-splits a template block and all its dependencies automatically — no dynamic import needed, standalone deps only.
  • Triggers: idle, viewport, interaction, hover, timer, immediate, or a custom when expression — combinable, OR semantics.
  • @placeholder → @loading → content (or @error) cover every state; companions ship eagerly, so keep them light and same-sized (CLS).
  • prefetch on … decouples fetching from showing; when is a one-way load door, not visibility.
  • An eager reference anywhere un-splits the chunk silently — verify in the build output; with SSR, know plain vs hydrate trigger semantics.
