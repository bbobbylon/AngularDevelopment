The View Transitions API animates between two DOM snapshots: freeze the old pixels, mutate the DOM, then animate old → new with plain CSS. Angular's router wires the whole thing up with one function, withViewTransitions() — and this very app uses it for every navigation you've already been clicking. Every section below is the same idea from a different angle: two photographs, and a dissolve between them.

The problem

Wire up a transition, forget one line. Predict what breaks.

Every demo on this page grows or shuffles cards inside a helper called withTransition. It looks almost too simple: run document.startViewTransition(), change a signal inside it, done. One line is missing from the version on the right, and it's the one line that makes the whole thing work.

The mental model

Two photographs, and a dissolve between them.

Forget "animating the page." Picture a photographer in a room. Before anything moves, they take a picture — that's the old snapshot. Then a curtain drops: behind it, inside your callback, the furniture gets rearranged — the DOM mutates, a route swaps, whatever you asked for. The audience never sees this part happen; the old photograph is still all that's on screen. The instant the crew steps back, the photographer takes a second picture — the new snapshot. Only then does the browser project both photos on top of each other and dissolve from one to the other.

If one piece of furniture — one element — wears the same name tag in both photographs, the browser does something smarter than a flat cross-fade: it slides, resizes and reshapes that one piece from its old spot to its new one. That's the entire "shared element morph" you'll meet later in this lesson, and it's why the API cares so much about names.

Two photographs and a dissolve: capture the old photo → mutate the DOM behind the curtain → capture the new photo → cross-fade (or morph any matching name tags) between them. Every section on this page is one of those four beats.

Across routes

Same name tag, two different pages — that's the entire trick.

Assign the same view-transition-name to a matching element on the old route and the new one. The browser pairs them by name and morphs — the classic "thumbnail expands into hero image" effect, no FLIP math, no animation library:

A view-transition-name is a name tag, and the rule is strict: at most one element wearing that tag, per page, at snapshot time. Put it on all ten cards in a list and the browser doesn't guess which one you meant — it throws the whole transition away and the navigation just happens instantly, unanimated.

Where this bites

Snapshots aren't the live page — and that bites in specific ways.

  • Snapshots aren't live: the old view is a bitmap — hover states, videos and canvases freeze during the transition, because you are looking at a photograph of them, not the real thing.
  • The page is non-interactive while a transition runs — a 2s artistic transition means 2s of dead clicks.
  • Names must exist on both sides for a morph; a name present only on one side just fades in/out as its own group.

Omitting the reduced-motion override means users with vestibular disorders experience forced animation on every navigation. Always add it. Browsers that don't support the API navigate instantly as a no-op — no polyfill needed.

Questions from the back row

Before you go

Recap — five things to remember.

  • Two photographs and a dissolve: capture old → mutate the DOM behind the curtain → capture new → animate old → new. The DOM must be truly updated before the callback resolves, or the second photo matches the first.
  • withViewTransitions() is one line; customise with ::view-transition-old/new(root) CSS.
  • Matching view-transition-name tags morph elements across states — unique per page, a duplicate name skips the whole transition instead of guessing which one you meant.
  • Name your sticky header so it doesn't cross-fade; keep transitions ≤250ms; always add the reduced-motion override.
  • Unsupported browsers degrade to instant navigation automatically — no polyfill, no extra code.
