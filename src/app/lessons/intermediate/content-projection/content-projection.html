Content Projection

Content projection lets a parent inject its own DOM into a child component's template. <ng-content> is the insertion point — the foundation of flexible card layouts, dialog boxes, tabs, and every other "shell" component. Angular 17+ adds signal-based contentChild() / contentChildren() to query projected nodes reactively.

The mental model: a frame, not a picture

A component with an <ng-content> is a picture frame. It decides the shape of the opening and everything around it — the border, the mount, the hook on the back. What it never does is make the photograph. The photograph was printed somewhere else, by someone else, on their paper.

Hold onto that and three otherwise-baffling behaviours become obvious. The child's styles do not reach the projected content, because the frame did not print the photo. The child cannot use viewChild to find it, because a view query searches what the child itself drew. And the photo gets printed whether or not the frame ever hangs on a wall — which is the trap in the next section.

View is yours; content is theirs. viewChild searches your own template; contentChild searches what was handed in from outside. One question settles it every time: did this component's template contain that node?

1 — Single slot (default)

The simplest form: one <ng-content> absorbs everything the parent puts between the component's open and close tags. 

// child component
@Component({
  selector: 'app-callout',
  template: `
    <div class="callout">
      <ng-content />   <!-- ← everything projected here -->
    </div>
  `,
})
export class Callout {}

// parent template
<app-callout>
  <strong>Heads up!</strong> This is projected content.
</app-callout>

2 — Multi-slot with select

Add a CSS select attribute to route specific content to named slots. Anything that does not match a selector falls into the bare <ng-content> (default slot). 

@Component({
  template: `
    <!-- select takes a CSS selector. [panel-title] is an attribute selector,
         so any element carrying that attribute lands in this slot. -->
    <header><ng-content select="[panel-title]" /></header>
    <!-- The unselected ng-content is the CATCH-ALL: everything that matched
         no other slot ends up here. There can be only one. -->
    <div><ng-content /></div>           <!-- default -->
    <footer><ng-content select="[panel-actions]" /></footer>
    <!-- ORDER MATTERS, but not the order you might expect. Slots are matched
         top-down, and each projected node goes to the FIRST slot it matches.
         Put the catch-all first and it swallows everything. -->
  `,
})
export class Panel {}

// parent
<app-panel>
  <!-- A bare attribute, no value needed — it's just a marker for the
       selector. Prefer attributes over classes here so a CSS refactor can't
       silently break the layout. -->
  <h3 panel-title>Invoice #42</h3>
  <!-- No marker → falls through to the default slot. -->
  <p>Body goes in the default slot.</p>
  <!-- ng-container carries the marker WITHOUT adding an element, so the
       footer gets the button and nothing else. Use it whenever you need to
       tag a group of nodes for one slot. -->
  <ng-container panel-actions>
    <button>Pay now</button>
  </ng-container>
</app-panel>
// The key idea: the PARENT owns the content and its bindings; the CHILD owns
// only where it appears. Projected nodes are created in the parent's context,
// which is why they can use the parent's fields and pipes.

3 — Fallback content

Place default markup inside <ng-content>. It renders only when the parent projects nothing into that slot. 

<ng-content select="[panel-title]">
  <span style="color:gray">No title provided</span>   <!-- fallback -->
</ng-content>

4 — contentChild() and contentChildren()

Signal-based queries that find projected directives or elements. They replace the decorator equivalents (@ContentChild / @ContentChildren) and update reactively when projected content changes. 

@Component({ selector: 'app-tab-group', … })
export class TabGroup implements AfterContentInit {
  // Returns a readonly Signal<readonly TabLabel[]>
  // CONTENT children, not VIEW children: these live in the PARENT's markup
  // and were projected in. viewChildren() would find nothing here.
  readonly labels  = contentChildren(TabLabel);   // ← directive token
  readonly panels  = contentChildren(TabPanel);
  // Because it's a signal, the result stays correct when the parent adds or
  // removes a tab at runtime — no manual QueryList subscription needed.

  ngAfterContentInit(): void {
    // This hook is the earliest point at which projected content is
    // guaranteed to exist. Read labels() in the constructor and you get [].
    // labels() is live — read it inside effect() to react to changes
    console.log(this.labels().length, 'tabs found');
  }
}

// Parent template
<app-tab-group>
  <!-- The parent writes a flat list. TabGroup discovers the structure by
       QUERYING for the directives, rather than the parent having to pass a
       config array. That is what makes this API feel declarative. -->
  <span tabLabel>Overview</span>
  <div  tabPanel>Overview content…</div>
  <span tabLabel>Settings</span>
  <div  tabPanel>Settings content…</div>
</app-tab-group>
// Pairing is POSITIONAL: labels()[i] goes with panels()[i]. Nothing enforces
// that, so a stray tabLabel with no matching tabPanel shifts every tab after
// it — the bug to look for when a tab shows the wrong content.

5 — ngProjectAs

ngProjectAs makes Angular treat a node as if it matched a different selector. Useful when a wrapper (e.g., ng-container) has to satisfy a select that targets a class or element. 

// child expects: <ng-content select=".badge" />

// parent — wrap several badges in ng-container, project as .badge
<app-badge-host>
  <ng-container ngProjectAs=".badge">
    <span class="pill">New</span>
    <span class="pill">Beta</span>
  </ng-container>
</app-badge-host>

Who creates projected content, and when

Projection vs. ViewChild — which query to use?

Situation Use
Query something inside the component's own template viewChild() / viewChildren()
Query content projected from the parent contentChild() / contentChildren()
Access a projected element's DOM node contentChild(SomeDirective) then .el.nativeElement
Query projected components (not directives) contentChildren(MyComponent)
Projected content keeps its original injection context. The projected nodes are created by the parent, not the child. This means services, tokens, and lifecycle hooks belong to the parent component tree, not the child that hosts the ng-content.
Projected content is always instantiated eagerly, even if its ng-content slot is hidden by @if in the child. To truly defer projection, use @defer in the parent or pass a template reference (TemplateRef) and render it lazily via NgTemplateOutlet.

Key takeaways

  • <ng-content> is where the parent's projected content renders.
  • select routes matching nodes to named slots; the bare one is the default.
  • Place fallback markup inside <ng-content> — it shows when the slot is empty.
  • contentChildren(Token) returns a live signal; query projected directives/components reactively.
  • ngProjectAs changes the selector match for a node without changing its real tag or class.
  • Projected content keeps its parent injection context — querying it uses contentChild, not viewChild.
