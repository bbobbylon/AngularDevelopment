Custom Pipes

A pipe transforms a value for display — formatting, filtering, mapping — without touching the component class. Decorate a class with @Pipe, implement transform(), add it to a component's imports, and use the | operator in the template.

Anatomy

@Pipe({ name: 'truncate', standalone: true })   // pure by default
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit = 20, trail = '…'): string {
    return value.length > limit
      ? value.slice(0, limit).trimEnd() + trail
      : value;
  }
}

// In a component:
imports: [TruncatePipe]

// Template — extra args follow the colon:
{{ '{{' }} title | truncate:40:'...' {{ '}}' }}

Demo 2 — sentenceCase (pure)

// `name` is what you type in the template: {{ '{{' }} text | sentenceCase {{ '}}' }}.
// It is NOT the class name, and it must be unique across everything the
// template imports.
@Pipe({ name: 'sentenceCase', standalone: true })
// implements PipeTransform is optional at runtime but worth keeping: it makes
// TypeScript check that transform() exists and is shaped correctly.
export class SentenceCasePipe implements PipeTransform {
  // The FIRST parameter is always the piped value — the thing on the left of
  // the |. Any further parameters come from :args in the template.
  transform(value: string): string {
    // charAt(0) rather than value[0]: on an empty string charAt returns ''
    // instead of undefined, so this doesn't throw on ''.
    // Note it returns a NEW string and never touches `value`. That purity is
    // what makes a pipe safe to memoise — see the pure/impure section below.
    return value.charAt(0).toUpperCase() + value.slice(1).toLowerCase();
  }
}

Demo 3 — filterBy (generic array filter)

A generic filter pipe takes an array, a field name, and a query string. This is the same pattern as the FilterLessonsPipe powering the home-page search in this app. 

@Pipe({ name: 'filterBy', standalone: true })
export class FilterByPipe implements PipeTransform {
  // GENERIC, so the pipe works on any array of objects and the return type
  // stays T[] rather than collapsing to any. `keyof T` then makes `field`
  // autocomplete to real property names — pass a typo and it won't compile.
  transform<T extends Record<string, unknown>>(
    items: T[], field: keyof T, query: string
  ): T[] {
    // Normalise ONCE, outside the loop, instead of per item.
    const q = query.trim().toLowerCase();
    // Empty query → return the ORIGINAL array reference, not a copy. That
    // matters: a fresh array every call would look like a change to OnPush
    // consumers and defeat the memoisation this pipe relies on.
    if (!q) return items;
    // String(...) coerces numbers, booleans and null safely, so filtering on
    // a numeric column doesn't throw on .toLowerCase().
    return items.filter(i => String(i[field]).toLowerCase().includes(q));
  }
}

// Template — arguments are colon-separated, in the order transform() declares
// them after the value: 'name' → field, query() → query.
@for (f of fruits | filterBy:'name':query(); track f.name) { … }
// This is PURE, so it re-runs only when `fruits`, 'name' or query() changes
// by reference. Push into `fruits` instead of replacing it and the list will
// not update — the classic filtering-pipe bug.

Live

@for (f of fruits | filterBy: 'name' : fruitQuery(); track f['name']) { {{ f['name'] }} } @empty { No fruits match. }

Demo 4 — relativeTime (pipe that injects a service)

Pipes run in an injection context — inject() works inside them just like in components. Here RelativeTimePipe injects Angular's built-in DatePipe as a fallback formatter. 

@Pipe({ name: 'relativeTime', standalone: true })
export class RelativeTimePipe implements PipeTransform {
  private readonly datePipe = inject(DatePipe);   // ← inject inside a pipe

  transform(isoDate: string): string {
    const diff = Date.now() - new Date(isoDate).getTime();
    const mins = Math.floor(diff / 60_000);
    if (mins < 60) return `${mins}m ago`;
    return this.datePipe.transform(isoDate, 'mediumDate') ?? isoDate;
  }
}

// Add DatePipe to the component's providers array.

Live

@for (post of posts; track post.id) {
{{ post.title }} {{ post.date | relativeTime }}
}

Demo 5 — highlight (impure, pure: false)

An impure pipe (pure: false) re-runs on every change-detection pass. Use it sparingly — only when you need to react to mutations inside an existing object or array reference. 

// pure: false makes this run on EVERY change-detection pass, not just when
// its inputs change by reference. Expensive — and here it is arguably not
// even needed, since term() is a signal that changes by value anyway.
@Pipe({ name: 'highlight', standalone: true, pure: false })
export class HighlightPipe implements PipeTransform {
  // Second parameter = the pipe argument: | highlight: term()
  transform(value: string, term: string): string {
    // Empty search term → return the input untouched, and skip building a
    // regex that would match everything.
    if (!term) return value;
    // The capture group ( ) is what $1 refers to in the replacement, so the
    // matched text is preserved inside the <mark>.
    // 'g' = replace every occurrence, 'i' = case-insensitive.
    return value.replace(new RegExp(`(${term})`, 'gi'), '<mark>$1</mark>');
    // WARNING worth knowing: `term` goes into a regex unescaped, so a user
    // typing "(" throws, and it goes into innerHTML below. Angular's
    // sanitizer strips scripts, but a production version should escape both
    // the regex metacharacters and the input text first.
  }
}

// Template: bind innerHTML because the pipe returns HTML
// Interpolation would print the literal "<mark>" characters on screen —
// [innerHTML] is what makes the browser parse them as markup.
<p [innerHTML]="sentence | highlight: term()"></p>

Pure vs impure — quick reference

Property Pure (default) Impure (pure: false)
Re-runs when Input reference changes Every change-detection pass
Memoized by Angular Yes No
Performance Fast Can be slow — use sparingly
Best for Formatting, filtering by value, mapping Reactive mutations inside existing refs
Alternatives — computed() reacts to mutations too and is faster
Before reaching for an impure pipe to filter a mutable array, try a computed() signal — it only re-runs when its dependencies change, not on every CD pass.
Pipes are standalone tree-shakable classes. Chain them freely: {{ '{{' }} value | truncate:30 | sentenceCase {{ '}}' }}. A pipe instance is reused — keep transform() free of hidden mutable state. All extra template arguments land in transform(value, ...args) in order.

Key takeaways

  • @Pipe({ name, standalone: true }) + transform(value, ...args) is all you need.
  • Pure pipes are memoized — they only re-run when the input reference changes.
  • Pipes can inject() services: DatePipe, HttpClient, I18n services…
  • For filtering reactive state, prefer computed() over impure pipes.
  • Standalone pipes live in a component's imports array — no NgModule needed.
