Every component ships its own CSS — and that CSS mysteriously never breaks the rest of the page. This lesson takes apart the machinery behind that: attribute stamping, the three encapsulation modes, the :host selector family, and the custom-property pattern that replaces the deprecated ::ng-deep.

The problem

Why doesn't this rule leak everywhere?

Here's a small thing that should bother you more than it does. Write p {{ '{' }} color: red {{ '}' }} inside one component's stylesheet, and only that component's paragraphs turn red — every other <p> on the page, including ones written by other teams in other files, stays exactly as it was. CSS itself has no idea what a component is. Nothing in the language stops a selector from matching everywhere it possibly can. So something outside CSS has to be actively stopping it — and, as you're about to see, it stops in only one direction.

A parent sets font-family: serif on <body>. Somewhere else, a different parent writes app-ve-badge .dot {{ '{' }} background: purple {{ '}' }} in its OWN stylesheet, aiming straight at a child component's internals. Both are ordinary rules, written from outside the component they affect. Which one actually reaches the child, and which one silently does nothing at all? There's a diagram and a live demo below to check yourself against.

The mental model

Encapsulation is a one-way window.

Picture encapsulation as a one-way window. Light gets in — the page's font, colours and custom properties reach every component without asking. But nobody outside can point at anything on the inside: a selector written in the parent simply never finds the child's elements. Most of the confusion in this topic comes from assuming a window that blocks pointing must also block light.

Encapsulation blocks selector matching, never value inheritance.

The selector you're missing

The tag itself belongs to the parent. Reach it with :host.

A component's scoped rules match elements inside its template. The tag itself (<app-ve-badge>) belongs to the parent's markup, so the child's own stylesheet needs a special selector to reach it at all: :host. The badge below is a real child component:

The parent writes [class.compact]="compact()" on the badge tag; the badge's own :host(.compact) rule does the rest. No inputs, no style piercing. (:host-context(.dark) extends the idea to ancestor conditions — theme switches.)

Custom elements default to display: inline — the single most common :host rule is :host {{ '{' }} display: block {{ '}' }}. If a component's width/margin "does nothing", check this first.

The trap and the fix

Parents can't reach in. Give them a knob instead.

A parent rule like app-ve-badge .dot {{ '{' }} … {{ '}' }} looks like it should recolour the dot inside the child. Before the next paragraph explains why it doesn't, predict it yourself:

The old escape hatch, ::ng-deep, pierces everything and is deprecated. The maintainable pattern is a styling API: the child consumes a CSS custom property, the parent sets it — inheritance carries it across the boundary.

Custom-property themed me too

One style binding on the wrapper — [style.--badge-accent]="accent()" — and every badge inside inherits it. The badge stays a black box.

Never write a selector aimed at a child's internals. Expose a custom property instead — that's the supported channel in, and it's why ::ng-deep stopped being necessary.

The idiom

Global tokens, component-scoped consumption.

  • styles.css (registered in angular.json's "styles" array) is document-wide: resets, typography, design tokens like --accent — this app's whole light/dark theme is custom properties flipped on <html>.
  • Component styles ship WITH the component — lazy-loaded pages bring their CSS along — and are scoped by encapsulation.
  • The idiomatic split: global tokens, component-scoped consumption via var().

Questions from the back row

Before you go

Five things to remember.

  • Emulated (default) = attribute stamping: styles cannot leak out; page styles still cascade in.
  • None = verbatim global CSS; ShadowDom = real isolation where globals stop working inside.
  • :host styles the tag; :host(.x) / :host-context(.x) make it conditional.
  • Parents cannot match child internals — expose CSS custom properties instead of piercing (::ng-deep is deprecated).
  • Encapsulation blocks selector matching, never value inheritance — that is why var() theming works.
